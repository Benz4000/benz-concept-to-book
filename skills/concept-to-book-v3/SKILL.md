# Concept to Book — Version 3

Establish the decisions that otherwise cause late rewrites or redesigns before their dependent work scales. Draft and produce to that foundation, then use later stages to revise and polish the planned book. Retain the ability to change direction when the user requests it or the evidence warrants it.

This skill is standalone. It requires no earlier-version installation, prior chat, private vault, other skill, publisher, or specific software. The bundled public example is synthetic, not a required input or a set of defaults. Version 3 moves late-discovered settings into a working foundation and retains version 2's outcome checks. Keep changes separate from `concept-to-book` (version 1) and `concept-to-book-v2` (version 2).

## Start with the user's end goals

Read available user decisions, project files, and current outputs. Determine the requested endpoint: concept/outline, manuscript, illustrated reading proof, publication files, or authorized platform action. Resume at the actual stage and stop at that endpoint. Do not infer publication authority from a request to write or format a book.

Create a compact goal register. For each goal record:

| Goal | Evidence and priority | Observable completion | Current gap | Owning stage |
|---|---|---|---|---|
| What the user wants readers or the deliverable to experience | Explicit request or labeled inference; requirement, target, or preference | Concrete evidence of the intended result | Unmet, met, uncertain, or not applicable | A–L below |

Distinguish the requested end from a proposed tactic. “Make the books feel equally developed” may require better scenes, not identical word counts. “Reduce wasted page space” may require layout repair, not another illustration. A particular number becomes a constraint only when the user makes it one.

Recover conflicting or superseded decisions. Apply the latest explicit choice to the affected goal. Ask only when the remaining ambiguity materially changes the work; otherwise state a reasonable assumption and progress. Stage completion is an evidence check, not a new permission gate.

For a new project or a workflow migration, read [foundation-settings.md](references/foundation-settings.md). It identifies preferences that emerged late, moves their decisions before dependent work, and supplies the foundation register and readiness checks. For retrospective evidence, [goal-audit-example.md](references/goal-audit-example.md) maps all 58 historical steps to their outcomes. Reuse the method, not the case study's settings.

The [public cover example](references/cover-workflow-example.md) is synthetic. Apply the complete CD01–CD12 sequence at the relevant dependencies; private conversations and source-specific values are omitted.

## Establish the foundation before scaling

Create or reconcile one **Book Foundation** with the goal register, accepted settings, source-use log, and intended reader-section inventory. Recover existing decisions first. For an ongoing project, fill missing settings around the current work; do not restart an accepted manuscript merely to create a new planning document.

Capture the following before the work they govern. Use a known decision, a clearly labeled reasonable assumption, or an explicit deferred item with a resolution milestone. Do not fill missing preferences with the example project's exact choices.

| Foundation area | Set early | Resolve before |
|---|---|---|
| Story and scope | Audience, premise, source/adaptation treatment, series/book scope, character arcs, setting/time, cultural boundaries, reveal strategy, ending intent | Detailed outlines and sustained drafting |
| Craft and depth | Available author-study principles, original voice, viewpoint, humor/wonder, readability, explanation level, punctuation preferences, benchmark scene depth | Bulk drafting; sample first when direction is uncertain |
| Structure and balance | Intended chapter experience/count flexibility, main/side-story roles, volume-balance measure, length targets versus quality priorities | Chapter architecture and planned content budgets |
| Complete reader package | Per-book prefaces, recaps, companions, epilogue, lore/afterwords, citations, author pages, guides, profiles, pronunciation, maps; purpose/order/spoiler boundary | Main drafting for narrative-dependent additions; final writing can follow stable canon |
| Identity and sources | Stable character/book IDs, working names/titles and alias policy, source edition, source-use tracking, citation/link presentation, supplied author text/photos | Repeated naming/citation work; final metadata before release |
| Visual plan | Art style, coverage roles/density, character continuity, image shapes, map/profile treatment, spoiler rules, cover family direction | Large image batches; scene briefs wait for sufficiently stable scenes |
| Edition and layout | Intended formats, trim/binding where relevant, typography, margins, furniture, blank/chapter-start policy, image placement, whitespace/balance preferences, preservation priorities | Representative proof and bulk assembly/art production |
| Completion and dependencies | Requested stopping state, required review coverage, exceptions, unresolved facts, owner and milestone for each deferred item | Any dependent commitment; actual final counts/templates remain late facts |

**Separate preferences from computed facts.** Decide the visual/edition strategy early; do not invent final page counts, assigned ISBNs, exact spine widths, printer processing, or scene-specific research that is not yet available. Mark deferred items as unknown with the stage that needs them. A deferred cover dimension must not block writing a chapter.

**Test the expensive assumptions cheaply.** When useful, use one representative outline, prose excerpt, supporting section, and small page/art sample to reveal conflicts before scaling. Reuse supplied or already accepted samples. For a concept-only request, record downstream choices as deferred and produce no unsolicited artwork or full production specification.

**Choose priorities before repeated repair.** Distinguish required settings from targets/preferences. Resolve foreseeable conflicts such as zero blanks versus recto-only chapter starts, exact page parity versus meaningful content, or image coverage versus page/quality limits. Use the user's expressed priorities; ask about a real unresolved tradeoff with a concrete example rather than administering a long intake questionnaire.

**Readiness:** dependent work may scale when its necessary settings are established, relevant conflicts are resolved, and open items have a safe, specific deferral. Record the working foundation version and the evidence supporting it. This is an internal readiness check, not a new approval requirement. New user direction can revise it.

## Execute the plan, then revise and polish

Use this sequence while retaining the stage letters below for ownership and change tracking:

1. **Foundation:** A plus the settings for E, F, H, J, and L. Determine available craft guidance, planned content and design preferences before they become costly to change.
2. **Planned creation:** B/C and the commissioned supporting material. Draft against the foundation; keep sources, canon, and the reader inventory current. Planned companions and arcs are part of this phase, not default late additions.
3. **Editorial revision:** D/E/F/G. Repair development, structure, prose, reader material, and continuity against the intended experience. Use an evidenced gap or new direction to justify substantial additions.
4. **Production:** verify H, then execute I/J using established specifications and sufficiently stable content. Finalize actual text/assets and assemble them; avoid reopening style choices without a reason.
5. **Polish and handoff:** K/L. Resolve rendered-page and cover defects, verify exact edition inputs, package the requested deliverables, and report their evidenced state.

Later review should normally improve execution of the agreed plan. It must not automatically commission more stories, mythology, profiles, illustrations, or another design merely because those options exist. Necessary restructuring remains allowed: identify the defect or new goal, update the foundation and dependent records, and scope the rework. Reducing avoidable overhaul is a process aim, not a promise that creative discovery will require no changes.

## Audit before proposing another pass

Compare current artifacts with the goal register and Book Foundation, then log concrete gaps. Every proposed task must have:

- An end goal and identifiable defect, unmet requirement, or new user request.
- A named artifact or reading scope to inspect/change.
- The reference needed, if any, and a reason to read it.
- A completion check and the outputs that the change may invalidate.

Combine tasks that share an outcome, authoritative inputs, and review scope. Separate work when its evidence differs: a structural scan, full consecutive reading, simulated reader response, independent beta/cultural review, and rendered-page inspection cannot substitute for one another.

Keep one active issue register per project. Do not create another undifferentiated “final final pass” when the existing list and review scope can answer the question. If the user explicitly requests a fresh comprehensive review, perform it and state its coverage. Otherwise, a completed check with unchanged relevant inputs remains valid.

## Twelve outcome stages

These are responsibility groups, not twelve mandatory passes or the order in which every decision is first made. The foundation establishes E/F/H/J/L preferences early; their later stages execute or verify them. Draft content must exist before full prose and reading reviews. A request for only a concept or outline normally ends at A or B.

### A. A clear creative contract

**End goal:** a recognizable story promise with coherent scope, audience, world, character change, and intended ending.

Define premise, audience, genre, original/adapted status, viewpoint, tone, practical character lives, stakes, world rules, setting/timeline, and the mystery's revelation limits. For adaptations, state what must remain recognizable and what may change. For series, give every book an achievement, cost, and contribution to the larger ending.

**Done when:** the Book Foundation resolves the choices needed for the next work, distinguishes settings from deferred facts, and records constraints, priorities, reader inventory, and relevant samples. Source/adaptation boundaries and reader-knowledge limits are usable by a writer. Reopen affected decisions for a changed premise, scope, world rule, major arc, ending, or user preference.

### B. An actionable, sufficiently researched architecture

**End goal:** chapters can be written at consistent depth without inventing missing causal steps or essential cultural facts midway through the series.

Map source episodes where relevant, character arcs, local agency, route/time, setups/payoffs, and knowledge ceilings. Plan the selected companion roles, home/family threads, finale/epilogue shape, and cultural encounters here when they are in scope. Give chapters viewpoint, place/time, objective, resistance, beats, consequential turn, and narrative function. Research questions that constrain those scenes and record material for the planned explanations/afterwords as research occurs. Distinguish traditional material from invented mechanics; retain differences between cultures and religions.

**Done when:** every planned unit has an actionable function and appropriate detail; necessary source questions are answered or explicitly bounded; routes, causality, and reveal sequencing work. Chapter counts are design choices, not substitutes for pace. Reopen affected plans when story requirements or supporting facts change.

### C. A complete draft at consistent depth

**End goal:** the entire promised story exists as readable prose with comparable attention across its parts.

Use the established voice and scene-depth benchmark, incorporate sample feedback, and draft in meaningful units. Write the planned narrative and companion material according to their roles rather than postponing all supporting-character development to revision. Consult current outlines, prior endings, and continuity. Track names, injuries, possessions, debts, promises, relationships, abilities, time, travel, and knowledge. Compile reading copies and checkpoints as units finish.

**Done when:** no planned story section is missing; scenes include action/resistance/consequence rather than outline summaries; any uneven development is identified. Counts distinguish main narrative from supplemental material. Expand only where a reader need is unmet. Reopen for missing story material or demonstrated depth gaps, not a numerical difference alone.

### D. Developmental revision against the plan

**End goal:** main and supporting characters make consequential choices; episodes build; the emotional and narrative endings are earned.

Audit the drafted relationships, cultural encounters, home/family threads, side-character agency, chapter rhythm, and ending against their planned functions. Consolidate demonstrated gaps into one revision plan. Fix existing scenes where that meets the goal; add or substantially restructure material when the gap warrants it or the user changes scope. Each addition needs a purpose, place in chronology, changed consequence, and effect on later scenes. Keep the main story intelligible and satisfying without optional companions.

**Done when:** important promises are paid off or intentionally left open; new scenes justify their space; chapter boundaries support pace; the ending demonstrates change. Update chapter-number maps and canon after restructuring. Reopen for new substantive content, changed outcomes, or a supported developmental defect. Do not grow the manuscript merely to equalize length.

### E. Voice and prose polish

**End goal:** humor, wonder, ordinary life, moral complexity, and accessibility serve this story's original voice.

Apply the foundation's craft criteria to character attention/wants, dialogue, sensory discovery, scene action, and explanatory repetition. Preserve intended period/local registers and the original project voice. Consult additional craft guidance only when an identified issue or user direction calls for it; log new source use. Do not make the end of drafting the default first discovery of available author influences or prose preferences.

**Done when:** the declared scope has been read and revised; representative examples demonstrate the criteria; duplicate explanation/actions and unintended voice problems are resolved. State whether a pass was selective or full. Reopen affected new/changed prose or a documented craft problem; do not repeat whole-series polishing without a purpose. Simulated feedback remains labeled simulation.

### F. Reader-package completion and polish

**End goal:** every included supporting section helps orientation, understanding, attachment, or source transparency.

Complete and polish the foundation's per-book inventory: requested prefaces, recaps, companions, epilogue, adaptation/folklore afterwords, bibliography, author pages, guides, and navigation. Draft canon-dependent summaries after their underlying events stabilize; include earlier books in the inventory check. Treat newly requested section types as explicit scope changes rather than routine polish. Preserve user-supplied identity/biography and maintain canonical titles/names and the planned link presentation.

**Done when:** each section has a reader purpose and correct placement; recaps/maps/profiles reveal only what their placement permits; sources identify actual editions/authors and uncertainty; all titles, aliases, links, and section order agree. Reopen only affected sections for canon, name, citation, identity, or inventory changes.

### G. An editorially coherent reading edition

**End goal:** the complete book/series holds together when read in its intended order.

After D/E/F stabilize, conduct the required integrated review: causality, pacing, names, route/time, knowledge, reveal gates, possessions, injuries, promises, capability limits, source boundaries, and endings. A full consecutive read includes all reader sections and has a coverage record. Distinguish it from scans and targeted checks. Track unresolved independent-reader/cultural feedback separately.

**Done when:** blocking issues and required coverage gaps are resolved; remaining items are accepted exceptions or explicitly deferred, nonblocking work; repaired scenes were checked in context; outlines, canon, individual files, and complete copies agree. Record reviewed content hashes/version. Later edits invalidate the affected checks and dependencies, not automatically every unrelated result.

### H. Verify the established edition specification

**End goal:** the book's format, reader experience, and manufacturing choices are known before large-scale layout/art production.

Retrieve the foundation's formats, trim, binding/paper strategy, metadata, typography, furniture, chapter-start/blank-page policy, visual coverage, placement, and space/balance preferences. Verify them against actual production requirements and a representative proof; resolve only the remaining relevant unknowns. Distinguish user preferences from platform requirements and correct conflicts before bulk production. Reuse a valid earlier sample instead of automatically redesigning it.

**Done when:** a representative proof demonstrates normal text, chapter openings/endings, images, and supplementary sections; required metadata has a reliable source or a clear unresolved status. Log any reused production code, fonts, or publisher decisions. Reopen when the user changes design criteria, the content format changes, or manufacturing constraints change.

For covers, H verifies the early CD01–CD03/CD05/CD08 choices in the [cover workflow](references/cover-design-workflow.md): authoritative design selection, title hierarchy, actual-font fit, relevant front/jacket crops, intended formats and reliable edition identity. Keep final count/template geometry deferred until real inputs exist; test costly design interactions before bulk art or assembly.

### I. A reproducible assembled manuscript

**End goal:** the reading outputs contain exactly the intended content and can be rebuilt from known inputs.

Freeze a source snapshot with hashes, section boundaries/order, metadata, asset versions, font origins, and build settings. Export requested editable and reading formats using available tools. Exclude editorial wrappers, private planning dates, obsolete backups, and duplicate source mirrors. Compare live hashes before applying staged changes so newer work is preserved.

**Done when:** all intended reader sections appear once and in order; text/section counts reconcile; no raw wiki markup or placeholders leak; output provenance and rebuild method are recorded. Rebuild after relevant source, asset, or layout changes. Do not require a historical builder or another installed skill.

### J. A coherent visual edition

**End goal:** maps, portraits, author images, and illustrations reinforce the story, respect knowledge limits, and fit the intended print area.

Execute the foundation's visual coverage, style, aspect-ratio, appearance, and placement plan against stable scene briefs. Source maps appropriately; anchor portraits to current appearance; use supplied photos for identity. Record prompts/source assets, scene purpose, spoiler limit, proportions, resolution, and intended placement. Generate the planned assets, then correct art/placement defects. A new coverage campaign or art direction is a foundation change, not an automatic polishing task.

**Done when:** planned assets are present and integrated; scene/appearance continuity passes; proportions, crop, resolution, and placement meet H or have explicit exceptions. Image count alone does not prove balanced coverage. A new image is not the default remedy for every blank region. Reopen for changed scenes/appearance, asset defects, or layout needs identified by K.

For cover imagery and supporting assets, J executes CD04–CD07 in the [cover workflow](references/cover-design-workflow.md): source-grounded scene/cast/appearance, independently controlled logo/type where useful, distinct copy-surface roles, and story-object icons with decorative interpretation labeled. Verify delivered pixels and applied crops; a requested resolution is not proof of a sufficient source.

### K. A verified rendered edition

**End goal:** the actual pages are readable, visually balanced, technically intact, and consistent with the chosen specification.

Audit the assembled version against the foundation and verified H specification: text completeness, font embedding/glyphs, margins, headers/folios/parity, navigation, chapter starts, line endings, blank/sparse pages, image sequences, cropping, overlaps, resolution, and agreed space targets. Inspect rendered pages, including adjacent pages around fixes. Use one defect list, group related repairs, rebuild, and recheck their effects. Resolve typography through layout before rewriting story text unless the user requests otherwise. Do not silently tighten gap limits, change blank-page policy, or add images to redefine completion during the acceptance pass.

**Done when:** relevant checks pass or exceptions are recorded against the exact output version; counts, bookmarks, links, manifests, and asset placements agree; verification scope is honest. A final acceptance review is required before claiming the edition meets its target. Reopen affected pages and downstream pagination/cover dependencies after any relevant change. A passed local audit is not printer approval.

For covers, K performs CD08/CD10/CD11 in the [cover workflow](references/cover-design-workflow.md): inspect actual front/back/spine/flap exports at readable scale, fit authorized copy at the agreed type treatment, and diagnose low versus excessive effective resolution per embedded object. Preserve approved layers during scoped repair, verify the relevant before/after differences, and disclose restoration provenance. A measured or sampled check establishes only its recorded scope.

### L. Matching covers and an accurate production handoff

**End goal:** each requested edition has suitable, spoiler-conscious artwork, matching production geometry, and a verified status.

Execute the foundation's cover-family direction, hero emphasis, and spoiler policy using final canon and character references. Prepare edition records and official templates when their real inputs are available. Finalize local wraps/jackets against the verified final interior page count, applicable manufacturing rules/template, ISBN, binding, paper, and trim; provisional inputs remain provisional. When platform processing provides or changes the manufacturing count, reconcile it with the template and cover before claiming platform acceptance. Local upload-file preparation need not wait for processing that has not occurred. Validate spine, safe areas, bleed, barcode space, typography, resolution, and output format.

Execute CD09/CD12 in the [cover workflow](references/cover-design-workflow.md): independently assemble each edition from its actual template, keep cropped previews and guide proofs distinct from submission files, and preserve the correct edition barcode/ISBN. Match the selected cover hash with the intended current interior, distinguishing canonical and transport derivatives. After an interrupted or manual upload, inspect persisted receipts and validation scope; a cover checked against an older interior does not establish the corrected pair. Report recorded receipt, validation, submission, processing and proof/distribution state separately.

**Done when:** the requested cover/files or authorized platform action are verified; unresolved imprint/metadata/template mismatches are visible. State each edition's highest evidenced state: reading proof, preflighted upload file, uploaded, processed, proof approved, or distributed. Interior changes reopen geometry checks. Uploads, purchases, approvals, and distribution require the user's actual authorization.

## Manage changes by their effects

Use the change-impact table in [goal-audit-example.md](references/goal-audit-example.md). Classify a change as a repair within the foundation, a refinement within existing choices, a deferred fact becoming known, or a new creative/design requirement. Update the foundation when a setting changes and identify which completed evidence no longer holds. Honor authorized new direction; do not treat the foundation as irrevocable or require approval already supplied by the user's request. Reuse unchanged sources/assets and completed checks. Record changed inputs, invalidated checks, scoped work, and restored status.

A new companion story can reopen D/E/F/G/I/J/K and pagination-dependent L. A source URL repair may need F/I/K link verification while leaving plot review valid. An image resize can need J/I/K and page-count-dependent L without a new literary revision. Match scope to actual effects; do not assume every tool change alters every book.

## Preserve reference transparency

Use [reference-provenance.md](references/reference-provenance.md) whenever consulting sources. Record exact source, stage/goal, location read, reading scope, actual application, destination, and limitations. Separate supplied literature, imported craft notes, internal canon, factual research, user materials, and production reuse.

Tell the user when a new vault reference materially affects work. Distinguish consulted/applied from merely available, unavailable, or historical use documented by a report. Do not claim fresh source consultation simply because established principles continue to guide revision. If there is no vault, proceed with supplied material and say no vault references were used.

## Deliver the outcome and audit trail

Report goal status, completed outputs, review evidence, remaining issues, references actually used, and the next concrete dependency if work remains. Stop when the requested deliverable is achieved; do not manufacture more improvement passes to keep working.
