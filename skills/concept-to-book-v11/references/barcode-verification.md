# Bounded digital barcode verification

`python -B scripts/verify_barcode.py --config /absolute/inputs/barcode-verify.json --output-dir /absolute/new-verification` calls `verify_barcode.verify_barcode(config_path, output_dir)`. Start with `assets/templates/barcode-verify.json`; placeholders deliberately fail validation. Output is JSON evidence and, when rendering succeeds, the actual `rendered-barcode.png` crop. A mismatch or unreadable symbol produces `status:failed` and CLI exit 2; unavailable decoder/renderer capability produces `status:capability-missing`, also exit 2. A malformed config or mismatched input hash raises `BuildError`. No library installation occurs.

Supply the explicit checksum-valid 978/979 ISBN-13 identifier for this edition, the actual source barcode image and its exact SHA-256, the actual one-page cover PDF and its exact SHA-256, and `barcode_region_pt:[x,y,width,height]` in PDF points with lower-left origin. The region must include the whole symbol and its quiet zones. Choose this box from the supplied cover placement evidence; it must lie entirely inside the actual zero-origin upright MediaBox. Inputs use safe relative paths within the config directory. Optional `renderer` is an existing pdftoppm executable/name; optional integer `dpi` is 200–600, default 300. The crop is bounded to 40 million pixels. Output must be a new directory outside the input directory.

Both the supplied image and an independent Poppler rendering of the actual cover region must decode to the exact explicit edition identifier. Reading a caption, finding an image object, preserving its pixels, or accepting the filename does not establish its encoded value. Successful source decode cannot compensate for wrong, clipped, hidden or unreadable bars in the actual cover. `status:verified` describes these two digital decodes only. `physical_print_scanner_acceptance` always remains `not-assessed`; obtain a physical proof and appropriate print verification separately. The check neither assigns an ISBN nor verifies ownership, publisher approval, color management or PDF/X.

Poppler reads an exact hash-verified PDF copy and writes its actual crop in an isolated short temporary working directory, using relative native arguments. The resulting crop is copied byte-for-byte to the requested final path and its digest is rechecked. This handles long Windows source/output paths without changing the authoritative source or result. Actual cwd, relative arguments and staged PDF hash are recorded. Cleaned temporary paths are execution provenance, not persistent handoff dependencies.

The local decoder deliberately supports one upright, axis-aligned, dark-on-light EAN-13 symbol, static PNG/JPEG, at least two pixels per module, and intact quiet zones. It checks observed run widths, guards, digit patterns, leading parity and checksum across at least three consistent scan rows. It supports no arbitrary search, rotation/skew, reversed bars, add-ons, error correction or other symbologies. Unsupported inputs remain unreadable; there is no guess or mock success fallback. Passing scan rows do not grade all bars or print quality. The encoding structure and quiet-zone rules are grounded in the primary [GS1 General Specifications, version 11, sections 5.2.3–5.2.4](https://ref.gs1.org/standards/genspecs/11.0.0/). This historical edition supports the stable encoding algorithm; it is not a claim about current printer acceptance requirements.

The manifest records source/cover hashes, explicit identifier, actual renderer binary SHA-256/version/DPI/crop coordinates, crop hash, independent decode values/rows, failure reasons and limitations. `validate_barcode(manifest_path, source_barcode=None, cover_pdf=None)` reopens current source/cover bytes and the renderer binary, verifies the saved crop hash, decodes both images again and recomputes status. Optional overrides support relocated byte-identical inputs. This is integrity evidence, not a signature or authenticated attestation that a human inspected a proof. The verifier never edits its source image or cover PDF.

`selftests/test_v10_review_barcode.py` uses ReportLab's independent EAN encoder to generate actual ISBN-compatible bars, then draws them into actual PDFs and renders them with Poppler. Cases include two matched decodes, wrong expected edition, source-correct/rendered-wrong edition, damaged bars, clipped quiet zone, blank image, missing renderer, stale hashes and source preservation. Test dispositions and example identifiers are synthetic validation fixtures; they do not certify a real book or a human review.
