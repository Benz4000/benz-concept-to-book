# Book foundation: establish, calibrate, and verify

V5 adds ready project records and observable acceptance criteria to this foundation. Use [project-records.md](project-records.md) to adapt templates into existing project records and [quality-and-priorities.md](quality-and-priorities.md) to define relevant criteria and prioritize dependent work. The historical timing below remains unchanged; no earlier version is required.

V6 also selects relevant [project profiles](project-profiles.md), distinguishes [story time and reader knowledge](continuity-and-knowledge.md), and records [source variants and adaptation choices](source-conflicts.md). Establish requested formats and applicable reading needs early; verify actual [production capabilities](production-adapters.md) and [format behavior](format-reading-checks.md) when real outputs exist. These are scoped extensions, not extra compulsory intake fields.

Version 3 changed **when decisions are made**; version 4 also records their scope, examples, implementation links, and evidence from connected pilots. Version 1 records the historical process; version 2 groups its work by outcome; version 3 brings foreseeable creative, content, visual, and production settings forward so the later work can concentrate on executing, revising, and polishing the intended book.

The linked public examples are synthetic. Establish current choices from actual user direction and available evidence; private project histories and source paths are omitted.

These categories do not impose numeric values or a new approval sequence. Keep them in existing scoped project records. A deferred identifier blocks dependent barcode verification, not manuscript work. The operational contracts are in [V10 completion workflow](v10-completion-workflow.md).

## Foundation-first planning inherited from version 3

Version 2 asks what an activity achieves and when to repeat it. Version 3 first asks which decisions that activity depends on can be established now.

| Work | Foundation decision | Later work's purpose |
|---|---|---|
| Prose | Available craft influences, original voice, readability, scene depth, stylistic preferences | Improve execution against those criteria; introduce new criteria only for a reason |
| Story development | Main/supporting arcs, cultural encounters, ending functions, intended companions | Fix missing consequences and weak scenes; add major material for an evidenced need or new direction |
| Reader edition | Per-book section inventory, purpose, order, spoiler boundaries, source presentation | Complete canon-dependent text, verify consistency, and polish |
| Art | Style, coverage roles, appearance policy, typical shapes, placement constraints | Generate the planned set and correct scene, quality, or placement defects |
| Page design | Format, type/navigation system, blank/chapter-start policy, relevant space targets, preservation priorities | Reflow and polish actual pages against an established specification |
| Covers | Series identity, hero emphasis, spoiler treatment, edition strategy | Finalize content and exact geometry when real manufacturing inputs exist |

“Established” means a decision has a value, evidence, status, and a point at which it must be verified. It does not mean the decision can never change. Stage readiness follows the next dependency, not completion of every possible publishing detail.

## Preferences that appeared late and where to move them

| Setting to capture | Establish in the foundation | What remains later |
|---|---|---|
| Craft influences and voice | Inventory available guides; read the applicable ones; translate them into criteria for this project's own voice before bulk drafting | Revise actual prose; consult newly supplied guides honestly when they arrive |
| Scene-depth standard | A representative outline/prose benchmark across different scene types or books, with action, resistance, social wants, and consequence | Diagnose thin scenes; do not make every scene equally long |

| Headers, footers, and navigation | Required placement/content, opening-page exceptions if desired, folio conventions, contents/bookmark behavior | Actual labels, page addresses, and rendered clearance |
| Whitespace and balance | Desired measure, which pages/body area count, threshold only if explicitly requested, intentional exceptions, and tradeoff priority | Measured final defects; actual page spread; no silent tightening during polish |
| Preservation and correction methods | Whether prose can change for layout; protected art/endings; allowable crop/reflow/extension; aspect-ratio and quality requirements | Concrete repairs and documented exceptions; do not distort art or pad prose |
| Cover direction | Brand/series identity, intended hero/event emphasis, spoiler policy, front-cover versus wrap strategy, edition variants | Final heroes/events from canon, exact template/ISBN/page-count geometry, printer verification |

Some story/source constraints were already established early in the example project. Keep them in the foundation rather than labeling every existing decision a late discovery. The opportunity is to capture additional high-impact preferences earlier when they are available.

## Decide early, test with samples, determine later

### Decide early

Recover accepted decisions and state the target reading experience. Record creative scope, available craft guidance, intended content, visual ambition, known format choices, and priorities. Treat missing preferences as open questions or working assumptions rather than silently importing case-study defaults.

For an ongoing book, identify where its existing accepted choices already satisfy the foundation. Preserve the current manuscripts and assets. Fill the gaps that affect upcoming work; do not demand an outline rewrite or discard a review merely because the project did not begin under this skill.

### Test before expensive repetition

Use relevant representative material to answer uncertain design questions:

- A chapter outline and a small prose set showing dialogue, ordinary life, action, and the intended tone.
- A supporting-section example if the edition includes distinctive profiles, recaps, or afterwords.
- A small proof showing ordinary text, a short ending, a chapter opening, a long heading, and representative image/navigation behavior.
- Art examples for the kinds of images actually intended, including a wide image if panoramas are part of the plan.

These are options selected by uncertainty, not a mandatory asset bundle. Reuse accepted examples or supplied assets. Do not generate hundreds of images to discover that their aspect ratio conflicts with the desired page design. A concept/outline-only request does not require a typeset proof or image generation.

Samples can settle settings without an extra confirmation round when the user's direction is already clear. If a sample exposes a meaningful unresolved preference, present the concrete tradeoff and continue independent work.

### Determine later

Never invent facts to make the foundation look complete. The following can remain deferred until their inputs exist:

- Exact final prose, successful emotional phrasing, and details discovered through genuine scene development.
- Final section/word/page counts and precise page addresses.
- Scene-specific appearance variants, final image placements, and available print space.
- Confirmed assigned ISBN, edition/provider imprint, final template, spine width, and platform processing.
- Actual beta/cultural feedback, printer/physical proof findings, and live publication state.

Each deferred item needs a **reason, resolution milestone, and dependent action**. For example: “Spine width: unknown until final interior and the relevant template are available; blocks final wrap geometry, does not block chapter drafting.”

## Readiness checkpoints

| Before | Necessary foundation | What may remain open |
|---|---|---|
| Detailed outlines | Story promise/scope, source treatment, major arcs and reader knowledge, intended content types, meaningful structure/balance priorities | Exact chapter titles/count allocation, final prose, final production measurements |
| Bulk drafting | Adequate outlines, usable voice/depth benchmark, recurring identity rules, essential scene research, planned narrative/companion roles | Canon-dependent recap/afterword wording, final art placements, ISBNs/spines |
| Bulk art/layout | Intended reader inventory, stable enough scene/appearance canon, art coverage/style/shapes, relevant edition/layout choices, samples resolving high-impact uncertainty | Final page totals and page-specific defects; final wraps |
| Full editorial reading | Selected reader inventory and major canon substantially stable; names/ordering current | Nonblocking later production facts; new creative discoveries may still require scoped revision |
| Rendered acceptance | Current manuscript/assets, specification, known targets/exceptions, reproducible assembly | Platform processing/physical proof when not yet in scope |
| Final cover geometry/handoff | Actual applicable interior count/template and edition identity, current cover canon, authorized endpoint | Only explicitly provisional or deferred deliverables; no false final/processed claim |

Readiness is proportional to the next substantial work. A missing ISBN does not stop writing, and an unresolved paragraph does not require redesigning every portrait. Conversely, uncertainty about illustrated versus text-only scope matters before commissioning hundreds of images.

## Later stages: revise and polish the intended result

| Later stage | Normal work | Treat as a foundation change when |
|---|---|---|
| Developmental revision D | Repair causality, agency, weak relationships, pace, payoff, or endings | A different premise/arc/ending, new content category, or major unplanned expansion is selected |
| Prose polish E | Improve voice, dialogue, sensory specificity, readability, and unwanted repetition | The desired voice, audience, influences, or fundamental prose treatment changes |
| Reader package F | Complete accurate recaps/afterwords/profiles, clean citations/links, verify inventory/order | A new supplement type or materially expanded companion scope is requested |
| Editorial integration G | Check the full reading experience and repair contradictions against current canon | New canon or section order changes what prior reading established |
| Production H/I/J | Verify the early specification, assemble, create/integrate planned art, correct asset defects | New art direction, coverage ambition, trim, typography, or page policy is chosen |
| Rendered polish K | Fix measured gaps/overflow/furniture/navigation/image fit against the selected target | Targets become stricter or the design policy changes, rather than an existing requirement failing |
| Cover/handoff L | Apply established identity and spoiler rules to exact available edition inputs | Cover direction or edition strategy changes; distinguish those from deferred facts becoming known |

Substantial revision is allowed when it serves the goal. Do not preserve a broken structure merely to keep the work “polish-only.” Identify the reason, revise the affected foundation decisions, and perform the appropriate development and dependency checks. Avoid disguising a new story commission or design campaign as routine proofreading.

## Handle changes without restarting everything

Classify the change before acting:

1. **Repair:** actual result fails an established setting or story purpose. Fix the discrepancy and its affected outputs.
2. **Refinement:** an improvement within established scope/choices. Make it when useful and recheck its effects.
3. **Deferred fact resolved:** a final count, template, or verified source fact becomes available. Complete its dependent work; revise assumptions if the fact contradicts them.
4. **New requirement:** the user changes the intended content, design, or endpoint. Update the foundation and perform the authorized change with a clear impact record.

Use the [change-impact table](outcome-stages.md) to scope reviews. Preserve unchanged evidence and assets. A source or user correction is not a reason to defend an old assumption; a new request is not evidence that the earlier accepted edition was defective.

Example: if a completed proof meets an established blank-page policy and the user now requests zero blanks, record a policy change. Reflow the affected books, repair parity/navigation and image relationships, and recheck page-count-dependent covers. Do not launch a new prose rewrite unless the change exposes a real text problem or the user requests one.

Example: if adding a planned companion exposes missing chronology, fix the narrative/continuity gap and recheck surrounding text. If the user instead commissions an entirely new set of companion stories, update the content inventory and perform scoped development. Both are allowed; only the first is a defect against the original plan.

## Preserve history and reference honesty

Consult applicable available craft guidance before dependent work when useful. Record when it was actually read and what changed; do not retroactively claim influence or require unavailable sources.

Retain every source's role: original literature, imported craft note, project canon, external cultural/geographic research, user biography/photos, or reused production code/metadata. When a source changes a foundation setting, record the setting, actual read scope, resulting decision, and affected outputs. A later source change may require a foundation update; continued use of an established principle does not prove fresh consultation.

Quantities, cultural setting, trim, blank-page and spacing choices are project-specific. Final page/image counts are measurements, not universal requirements.
